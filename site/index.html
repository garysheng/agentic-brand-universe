An open standard · v0.5 · 2026

Every brand becomes a version-controlled universe its agent can render on demand.

The Agentic Brand Universe is an open standard for building brands as living, version-controlled canon instead of a static PDF. Define the brand once — its characters, settings, motifs, rules, and blessed "golden" assets — and an agent projects that canon into any deliverable, on brand, on demand, with provenance. It's the end of brand slop.

The model

Cartridge + console → anything you want

Three distinct things, and once you see them apart, the whole standard clicks. A brand universe is the data. A Brand OS is the runtime that loads it. A projection is whatever it renders.

The cartridge · data Brand Universe A portable, version-controlled brand: canon (characters, settings, motifs, rules) + blessed golden assets. Forkable. Rentable. This is what the standard defines.
+
The console · runtime Brand OS A deployed engine that loads a universe and generates any on-brand deliverable from it — in plain language, held to the brand's rules, every output carrying provenance.
→
The output · medium-neutral Projections Whatever the OS renders from the universe.

The universe is the codebase.  The OS is the runtime.  The deliverables are what it runs.

1 · the data
Agentic Brand Universe
the cartridge
A brand as a typed, git-versioned canon plus its golden assets. Portable enough to fork or rent. This is the object the spec standardizes — the cartridge format every OS can read.
2 · the software
Agentic Brand OS
the console
A deployed runtime that loads a universe and generates deliverables from plain-language requests — on brand, held to the rules, with provenance. The working example: the AITX Brand OS.
3 · the output
Projection
the deliverable
Any single thing the OS spits out from a universe — a book, a flyer, merch, a meme, a thank-you. Medium-neutral: same canon, same spec, many projections.

Why it stays on brand

Canon is the source of truth. Everything else is a projection of it.

Three mechanics keep a thousand outputs looking like one brand — wired as steps the OS runs, never left to a person to remember.

🧬
References carry identity
Every character, setting, and motif resolves to a real, blessed reference asset — or the render fails loudly. A reference you can forget is a wish, not a standard. This is what kills drift.
🏅
Golden assets carry taste
The brand's blessed "golden" outputs become the anchors every new render is conditioned on. Taste is captured once and reused forever, instead of re-argued every time.
🧾
Every output carries provenance
A deliverable knows which canon it came from and which references it used. Nothing vivid ships unsourced. The brand can always answer "where did this come from?"
⛲
Canon is version-controlled
The universe lives in git. Every change is a commit, every contradiction a diff. "What did the brand look like when we shipped that campaign?" is a checkout, not a memory.
🧭
A deterministic prompt compiler
The OS assembles each render's prompt straight from canon, so a rule the brand already carries can't be silently dropped. The input is deterministic; a read-back gate still checks the output.
🚦
A load-bearing render gate
No deliverable renders until its references resolve and its checks pass. Quality is a set of wired gates, not a hope. Human taste sits exactly where taste is irreducible.

Why a standard, not a tool

Brand-neutral and medium-neutral, by construction.

A tool locks you into one vendor, one look, one medium. A standard defines the cartridge format — so any OS can load any universe, and any universe can render into any medium. Your brand is data you own, not a subscription you rent.
